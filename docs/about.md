# 关于与维护

## 这个库解决什么问题

以中文梳理开放词汇分割论文的研究问题、输入输出、方法和证据。3D 点云是重点，其他模态用于理解不同研究者如何解决相关问题。目标约100篇，采用弹性方向配额，不为凑数引入弱相关文献。

## 收录与阅读状态

1. 优先正式发表在相关重要会议、期刊且方法具有代表性的工作。
2. 非3D方向优先近期、已有实际官方实现、实验设置清楚的工作。预印本单独标记。
3. `已建索引`：核查身份、来源及官方代码公开情况；本批已补充定向方法模块，但尚未完整精读。
4. `样例笔记`：按统一模板解释方法与实验，并记录原文版本和证据位置；不代表完成逐行代码核查或复现。

当前涵盖3D、2D、视频、多视角、3DGS和遥感；RGB-T、多光谱、音视频、医学方向将按相关性继续扩展。

## 方法路线如何提取

先确定研究关注的问题，再提取原文中实际使用的相关模块；模块不必属于论文的主要创新。两条阅读主线分别整理开放词汇能力的实现，以及点云语义的传递、蒸馏和几何区域处理。混合模态工作逐模块归类，NeRF／3DGS 不自动计入点云主线。

每项记录包含问题、操作、输入输出、使用阶段、必要监督、方法来源及原文定位。方法来源分为“本文提出”“沿用已有方法”“在已有方法上修改”“来源未核实”。前者仅表示本文明确介绍这一设计，不代表对历史首创性的独立审计。沿用模块附原文引用来源；未核实的历史归属明确保留。

路线使用“语义来源 → 相关操作 → 输出表示 → 预测／用途”四个维度。它是模块处理路径，不是论文继承图，也不声称所有模块可以依次拼成同一个系统。点击节点或连线，比较表显示对应模块，展开后可追溯原图与章节。

图按当前研究问题、模态及关键词过滤后的记录计算权重。同篇论文在当前主线中的全部可见模块共贡献 1，每个模块贡献为该论文可见模块数的倒数；每一段转换守恒。带宽表示记录覆盖量；节点标注的是实际不同论文数。路线选择只高亮和过滤下表，不改变底图权重。颜色在后续阶段仍保留语义来源。手机一次展示两个相邻阶段，避免挤压标签。

交互路线结构参考 [4DGS 调研的研究路线页](https://joen.site/4dgs-survey/zh/methods/routes)。本站按研究关注点重新定义维度，独立实现可视化与模块数据。

## 原图与阅读路径

优先使用独立模块图或对应子图；没有独立图时保留主架构图并指明模块、区域或连接路径。主图未画出的操作明确说明，以原文文字和公式解释。保留图内原始符号、图例，不重绘成未经作者确认的架构。

`figures` 元数据记录图号、PDF 页码、精确版本、原始链接、裁切坐标与源文件 SHA256。正式提取图位于 `docs/assets/figures/`，下载 PDF、页图、预览及校验文件留在 `.codex_tmp/`。原图支持点击放大。正文不会添加跨模态迁移建议。

展开图解还可查看论文主要实验结果原表。`results` 保存表图、表号、版本、页码、来源、实验设置、指标方向和看表重点；模块可通过 `result_tables` 选取对应任务的结果。原表保留基线、分组、脚注及作者强调，不截掉不利结果，也不把不同监督、类别划分或硬件条件合成排行榜。主结果描述整体方法的效果，单个模块作用须结合原文消融。表格可放大并打开原尺寸，正式图片位于 `docs/assets/results/`。

## 四种证据标签

| 标签 | 含义 |
| --- | --- |
| 【原文事实】 | 在注明版本的论文中读到的方法、结果或限定条件 |
| 【官方文档说明】 | 作者仓库 README 等文档的陈述，未等同实际执行路径 |
| 【代码事实】 | 已实际检查实现及调用链的结论，必须写明路径和符号；本批样例未做此级审计 |
| 【分析推断】 / 【待验证假设】 | 整理者的解释、比较和设想，不能当作作者结论 |

## 开源状态怎么理解

- **已公开实现**：找到了官方仓库中的实际代码与使用入口，不只是占位页面。
- **部分公开**：只有部分步骤，关键实现或依赖缺失时另行说明。
- **计划公开**：官方只承诺将来发布。
- **尚未确认**：本轮没有找到可靠官方实现，不等于断言作者明确不开源。

公开代码、提供权重链接、能下载权重、能运行、能复现论文结果是五件不同的事。本库首轮仅检查前两类材料，尚未独立验证下载与运行。模型依赖和许可条件以原仓库为准。

## 内容如何更新

源笔记位于 `docs/papers/`。一篇论文一份 Markdown，YAML front matter 记录结构化字段，`methods` 和 `figures` 保存模块及配图；路线、比较表、论文页相关模块、列表、时间线和矩阵由构建脚本生成。技术和数据集使用 `data/taxonomy.yaml` 中的受控标识；模块主线、问题、来源及四维结构在 `scripts/methods.py` 校验。

GitHub README 也按研究方向列出所有论文、官方代码与仓库内笔记入口。它与网站共用论文元数据，更新后先同步清单，再构建网站。

新建条目时复制论文模板，将文件名设为稳定 `paper_id`，替换示例来源与字段。身份核查未完成前保持索引状态，不填造未知作者、数据和公式。标题和会议更新时保持 ID 不变；同一工作的预印本和会议版不重复计数。

```bash
.codex_tmp/venv/bin/python scripts/update_readme.py
.codex_tmp/venv/bin/python scripts/build.py --check
```

校验会检查字段、ID、受控标签、关系引用、样例章节、模块证据、四维路线和配图文件，再严格构建并检查站内链接。脚本不会自动检查外部链接的实时可用性。

## 部署与本地浏览

推送 `main` 后，GitHub Actions 自动校验并发布 GitHub Pages。PR只校验和构建，不部署。网站地址和本地启动命令见[仓库说明](https://github.com/buzhidaozenmo/Open-Vocabulary-Segmentation-Atlas)。

浏览器全文搜索和组合筛选在客户端运行，无需数据库或账号。JS不可用时论文库保留完整静态索引。筛选条件可从地址栏复制分享。
